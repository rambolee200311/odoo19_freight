# tk_freight 业务铁律

## 范围铁律

- 客户主体：中国天津出口代理货代企业。
- 核心业务：出口货代报价管理、订舱流程、货运单全生命周期管理。
- 财务核心：货运单绑定收入、成本、应收账款、应付账款核算与对账。
- 只围绕 `mymodules/tk_freight` 开发；不阅读/跟进 Odoo 官方源码。

## 已确认业务口径（2026-08-11）

1. 收入 = shipper + consignee 服务行的开票金额；成本 = vendor 服务行的账单金额。
2. 费用可分可合：费用行指定开票对象，可多客户/多供应商，可分多张发票/账单；一个费用行对应一张客户发票或一张供应商账单。
3. 本位币人民币；允许外币报价/开票；货单汇总按 Odoo 汇率表折算，收入/成本按单据日期，收付款按登记日期。
4. 费用行录入不含税单价 + 税率，自动计算税额与含税单价；税额和含税金额可手工修改；费用类型可配置默认税率。
5. 开票时点由操作员决定，手工触发创建发票/供应商账单，生成 Odoo 草稿单据。
6. 无网上银行；财务在 Odoo 内登记收付款，不建设复杂核销界面。
7. 利润 = 已开票收入（含税） − 已确认成本（含税） − 税费净额（销项税 − 进项税）。
8. 货单阶段不强制状态机；不建设价目表、报价审批等精细报价管理。
9. 报表需求、角色权限后续确定；遗留字段、向导、方法保留兼容，不删除。

## 流程铁律

- 主链：报价 → 订舱 → 货单 → 服务费 → 客户发票/供应商账单 → 收付款登记 → 货单账务汇总。
- 开票对象必须明确：服务行缺少 `shipper_id/consignee_id/vendor_id` 时不得参与开票。
- 发票/账单状态变化必须回写服务行与货单账务汇总。
- 不因门户、报表等未定需求阻塞财务口径落地。

## 数据铁律

- 财务字段金额默认按公司本位币展示，原币保留在单据上。
- 税率/税额变更必须走费用行录入，不在发票上随意改口径。
- 数据检查一律使用 `odoo shell`，非万不得已禁止直连数据库操作（铁律，2026-08-11 确认）。
- 任何业务口径调整必须先登记 `history/decision_note.md`，再改代码。

## 工程铁律（2026-08-11 确认）

- 模块升级一律用常驻方式启动 Odoo，使用 XML-RPC 升级模块，复现人类工程师升级流程。
- 升级出错必须检查 log 文件（`debug_logs/odoo_190.log`）。
- 禁止仅用 `-u --stop-after-init` 作为模块升级最终验证。
