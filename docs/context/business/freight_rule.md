# tk_freight 业务铁律

## 范围铁律（BUSINESS_FACT）

- 客户主体：中国天津出口代理货代企业。
- 核心业务：出口货代报价管理、订舱流程、货运单全生命周期管理。
- 财务核心：货运单绑定收入、成本、应收账款、应付账款核算与对账。
- 只围绕 `mymodules/tk_freight` 开发；不阅读/跟进 Odoo 官方源码（CONSTRAINT）。

## 已确认业务口径（BUSINESS_FACT，2026-08-11 用户确认）

1. 收入 = shipper + consignee 服务行的开票金额；成本 = vendor 服务行的账单金额。
2. 费用可分可合：费用行指定开票对象，可多客户/多供应商。
3. 本位币人民币；允许外币报价/开票。
4. 费用行录入不含税单价 + 税率，自动计算税额与含税单价；税额和含税金额可手工修改；费用类型可配置默认税率。
5. 开票时点由操作员决定。
6. 无网上银行；财务在 Odoo 内登记收付款，不建设复杂核销界面。
7. 利润 = 已开票收入 − 已确认成本 − 税费（税费净额解释见待确认口径）。
8. 货单阶段不强制状态机；不建设价目表、报价审批等精细报价管理。
9. 报表需求、角色权限后续确定；遗留字段、向导、方法保留兼容，不删除。
10. 数据检查一律使用 `odoo shell`，非万不得已禁止直连数据库操作（CONSTRAINT）。

## 待确认口径（ASSUMPTION / NEEDS_CONFIRMATION）

- A-1 费用行是否允许行级分批开票（现方案默认整行进一张发票）。
- A-2 汇率折算日期：收入/成本按单据日、收付款按登记日（未确认）。
- A-3 税费净额 = 销项税 − 进项税（利润公式的解释，未确认）。
- A-4 手工税额开票机制：与税率计算不一致时使用定额税码（未确认）。
- A-5 开票生成 Odoo 草稿单据（未确认，属方案）。
- A-6 服务行缺少 shipper/consignee/vendor 时禁止开票（未确认，属修复建议）。
- A-7 发票/账单状态变化必须回写服务行与货单账务（未确认，属目标设计）。
- A-8 货单财务字段默认按公司本位币展示、不在发票上改口径（未确认，属建议）。

## 流程铁律

- 主链（CODE_FACT）：报价 → 订舱 → 货单 → 服务费 → 客户发票/供应商账单 → 收付款登记 → 货单账务汇总。
- 财务联动必须走 `account.move` / `account.payment` 标准模型（CONSTRAINT）。
- 业务口径调整必须先登记 `history/decision_note.md` 与 `business/knowledge_classification.md`（CONSTRAINT）。
